# 《双界行者》怪物动画素材包 v1

本包对应已经确认的 4 种普通怪、2 种精英怪、1 种首领，共 14 个光暗形态。包含本体关键帧、独立攻击关键帧、透明动作图集、几何预警图、离线动画预览、逐帧索引与技能参数。

实际交付：**2,066 张本体帧（含左向镜像）、288 张攻击特效帧、80 张预警帧，共 2,434 张独立 PNG 帧**；另有 584 张横向动作图集、34 张生成源图、80 张预警 SVG 和 22 个技能配置。

先打开同目录的 **预览.html**。直接双击即可使用，不需要联网、安装工具或启动服务器。请先完整解压 ZIP，再打开预览，不能只把 HTML 单独取出。

## 3. 本体动作覆盖

全部形态包含 idle（待机）、move（移动）、attack_windup（主攻击前摇）、attack_release（出招）、attack_recovery（收招）、hurt（受击）、death（死亡）。三个绘制朝向为 front、right、back；left 由 right 水平镜像，已另存 PNG 和图集，不需要引擎再次翻转。

精英追加第二技能前摇、出招、收招与 guard。Boss 追加两套专属技能前摇、出招、收招以及 transform（相位收拢）。这不是只有站姿的概念图，每个动作都有多个独立关键帧。

多数动画为 4 帧；少数源图包含 5 个有效姿态时按实际数量保留，禁止把播放器写死为 4 帧。具体帧数以 manifest.json 为准。移动、漂浮和受击是关键帧级动画，不是高帧数逐帧精修动画；最终游戏可按动作时长播放并进行必要的美术润色。

## 4. 尺寸和锚点——避免忽大忽小

本次实际导出采用比最初设计更宽的留白画布，以容纳横向武器和死亡姿态。**此处与 manifest.json 优先于旧设计文档中的建议尺寸。**

|类别|单帧画布|根锚点（左上角坐标系）|
|---|---|---|
|普通怪|256×256|(128,224)|
|精英怪|320×320|(160,280)|
|首领|448×448|(224,392)|
|独立攻击特效|256×256|(128,128)|
|几何预警|256×256|(128,128)|

根锚点代表落地或地面投影参考点。所有同类帧保持相同画布；左侧镜像已平移校正到相同根锚点。切换动画时不要依据可见包围盒再次缩放或自动裁边。

人物大小按整套素材标定：灯魇约 84px，狼体高约 90px，傀儡约 128px，法师约 116px，执刑者约 174px，鸣钟约 168px，Boss 约 256px。它们大致对应上一版玩家站立约 128px 的尺度。光暗形态分别按待机高度校准至相同目标；本体的整套动作使用统一缩放，专属技能源图单独按参考姿态标定一次，不逐帧拉伸。

这些尺寸是角色设计的体型基准，不是每一帧都必须达到的高度。蹲伏、出拳、后仰和倒地会改变画面占用范围。源图的细微透视、盔甲和肢体比例仍可能存在生成式变化，不能仅靠统一画布完全消除。

攻击图的画布虽然都为 256×256，实际可见大小不同：小弹约 32px、针约 56px、矛约 144～196px、斩击/冲击波更大。请按设计中的实际距离设置碰撞，不能把 256px 画布都当作伤害范围。

## 5. 最小接入流程

1. 加载 manifest.json，按 enemy/form/kind/action/direction 找到动画。
2. 预加载所需的 atlas；用 frameWidth、frameHeight 和 frameCount 定位当前源矩形。
3. 绘制位置为 `(世界根位置 - pivot × 统一显示倍率)`，同一个怪物的所有动作使用同一显示倍率。
4. 状态机采用待机/移动 → 前摇 → 出招 → 收招，受击和死亡按规则打断。
5. 从 combat_profiles.json 读取技能前摇、有效时间、收招。不要把 defaultFps 直接当作技能时长。
6. 前摇结束只触发一次 release，创建独立子弹或近战判定；其后的飞行、寿命与碰撞不依赖本体动画继续存在。
7. 命中时销毁或标记攻击实体，再生成独立命中特效。受击无敌期与每次攻击命中集合在战斗逻辑中处理。
8. 仅渲染并判定当前世界的敌人攻击；清弹脉冲只处理 pulseClearable=true 的弹丸。

建议用点采样显示像素素材。非整数放大仅供预览，正式像素美术尽量采用 1×、2× 等整数倍率。

## 6. 预览页的功能与边界

可以选择怪物、光暗形态、本体或特效、动作、朝向；支持暂停、从头播放、单帧检查和显示比例调整。技能模式显示本体状态与独立攻击的释放时间，预警和攻击放在旁边的演示区，方便检查是否确实分层。

预览不模拟真实碰撞、追踪转向、弹幕数量、多段伤害、相位能量或完整 Boss AI。它也不会自动证明数值已经平衡。此类规则由 combat_profiles.json 和战斗设计文档描述，需在游戏中实现和试玩。

## 7. 品质与使用注意

- 本包是可导入的生成式关键帧原型素材，不等同于人工逐像素精修后的正式发行美术。
- 正面和背面的部分出招差异较细微，主要动作读取以侧面较清晰；请在实际镜头大小下检视。
- 左向来自镜像，会交换非对称武器的持握侧。这一点已在 manifest 中记录；若游戏强制固定左右手，需要另做左向原画。
- 根锚点已统一；嘴部、手掌或矛尖插槽未做逐帧人工标注。文档给出接入方法，不能把自动根锚点冒充精确的手部插槽。
- 普通 body 图不包含飞出的子弹。实体武器、盔甲上的装饰和眼部亮光仍属于角色；投枪/施法时对武器显隐仍需结合角色图检视。
- source_sheets 是美术来源，行列间距和帧数可能不规则；引擎请使用 atlases 和 manifest，不能重新等分 source_sheets。
- 请阅读 qa_report.json 与最终校验说明；数值参数仍是首轮试玩建议。

完整生成提示词、修订提示词、每帧来源和缩放保留在包内。需要调整某个怪物时，可替换对应文件夹，不必重做其他怪物。
